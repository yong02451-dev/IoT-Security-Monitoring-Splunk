# IoT Security Monitoring and Logging with Splunk SIEM

## 1. Project Overview

This project demonstrates the integration of an IoT-based RFID access control system with Splunk SIEM for centralized security logging, monitoring, and alerting.

The system uses a NodeMCU ESP8266 and an RC522 RFID reader to authenticate access cards. A servo motor controls the door-lock mechanism, while security events and device health information are forwarded to Splunk through the HTTP Event Collector (HEC).

The primary objective is to demonstrate how SOC analysts can collect, monitor, and investigate security telemetry generated by IoT devices.

## 2. Project Objectives

- Implement centralized logging for an IoT access-control device.
- Monitor successful and failed authentication attempts.
- Track door unlock and lock activity.
- Monitor Wi-Fi connectivity changes.
- Monitor device availability through periodic heartbeats.
- Create Splunk searches and dashboards for security monitoring.
- Configure alerts for device availability issues.

## 5. Security Events

| Event | Description |
|---|---|
| AUTH_SUCCESS | RFID authentication succeeded |
| AUTH_FAILED | RFID authentication failed |
| DOOR_UNLOCKED | Door unlock action |
| DOOR_LOCKED | Door lock action |
| WIFI_CONNECTED | Initial Wi-Fi connection |
| WIFI_DISCONNECTED | Reported Wi-Fi disconnection |
| WIFI_RECONNECTED | Wi-Fi connection restored |
| DEVICE_BOOT | Device startup |
| DEVICE_HEARTBEAT | Periodic device health event |

## 6. SOC Monitoring Use Cases

### Authentication Monitoring
Monitor successful and failed RFID authentication attempts to understand access activity.

### Failed Access Detection
Identify repeated unsuccessful authentication attempts that may indicate unauthorized access attempts.

### Device Health Monitoring
Use periodic heartbeat events to determine whether the IoT device is still reporting telemetry.

### Network Connectivity Monitoring
Monitor Wi-Fi disconnection and reconnection events to identify connectivity interruptions.

### Device Availability Alerting
Generate an alert when the device stops sending heartbeat events.

## 7. Splunk Monitoring

The project includes SPL searches for:

- Authentication monitoring
- Failed access attempts
- Device health monitoring
- Wi-Fi disconnection monitoring

It also includes a device-offline alert based on missing heartbeat events.

## 9. Security Considerations

- Credentials and HEC tokens must never be committed to the repository.
- Use HTTPS for event transmission.
- Restrict access to the Splunk HEC endpoint.
- Rotate exposed credentials and tokens.
- Monitor device availability and unexpected connectivity changes.

## 10. Project Scope and Limitations

This project demonstrates basic IoT security telemetry collection and SOC monitoring.

Wi-Fi disconnection events indicate connectivity loss but do not independently prove a deauthentication attack. Additional network-level monitoring would be required to identify the cause.

## 11. Future Improvements

- Implement reliable event queuing during network outages.
- Improve event timestamps and device identification.
- Detect repeated failed authentication attempts by card UID.
- Integrate network-level monitoring for Wi-Fi attack detection.
- Expand Splunk dashboards and alerting capabilities.
