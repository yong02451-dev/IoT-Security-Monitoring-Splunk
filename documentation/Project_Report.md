# IoT Security Monitoring and Logging with Splunk SIEM

## 1. Project Overview

This project demonstrates the integration of an IoT-based RFID access-control system with Splunk SIEM for centralized security logging, monitoring, and analysis.

The system uses a NodeMCU ESP8266 microcontroller connected to an RC522 RFID reader and an SG90 servo motor. Registered RFID card identifiers are stored in EEPROM and used for access-control decisions.

Security events generated by the device are transmitted to Splunk Enterprise through the HTTP Event Collector (HEC) using HTTPS.

The main objective is to demonstrate how security telemetry from an IoT device can be collected, analyzed, and monitored in a SOC environment.

## 2. Project Objectives

- Build an RFID-based IoT access-control prototype.
- Authenticate RFID cards using locally stored records.
- Control a servo motor based on authentication results.
- Generate security events from the IoT device.
- Forward events securely to Splunk using HTTPS.
- Monitor authentication activity and device health.
- Develop Splunk searches for SOC monitoring and detection.

## 4. System Architecture

The system consists of three main layers:

1. **IoT Device Layer:** Reads RFID cards, checks registered users, controls the servo, and generates events.
2. **Communication Layer:** Transmits JSON-formatted events over HTTPS.
3. **SIEM Layer:** Receives events through Splunk HEC, stores them in the `rfid_auth` index, and supports monitoring and alerting.

See [System Architecture](System_Architecture.md) for the detailed architecture diagram and data flow.

## 5. RFID Authentication Workflow

The authentication process works as follows:

1. A user presents an RFID card to the RC522 reader.
2. The reader obtains the card UID.
3. The ESP8266 compares the UID against registered records stored in EEPROM.
4. If a matching record is found, authentication succeeds.
5. The servo rotates to simulate unlocking the door.
6. After four seconds, the servo returns to its locked position.
7. If no matching record is found, access is denied.

The current implementation uses UID matching. It does not provide cryptographic authentication of the RFID card.

## 6. Splunk Integration

Splunk Enterprise receives events from the ESP8266 through the HTTP Event Collector.

### Event Transmission Flow

1. The ESP8266 generates an event.
2. The event is formatted as JSON.
3. The device establishes an HTTPS connection.
4. The HEC token is included in the HTTP Authorization header.
5. Splunk HEC receives the event.
6. Splunk indexes the event in `rfid_auth`.

### Configuration

| Parameter | Value |
|---|---|
| Splunk server | Configured Splunk Enterprise host |
| HEC port | 8088 |
| Ingestion endpoint | `/services/collector/event` |
| Index | `rfid_auth` |
| Transport | HTTPS |
| Event format | JSON |

Credentials and HEC tokens must be kept outside the public repository.
